# Manifest contract: m3.4.production.v1

`execution_manifest.json` records schema, generation identity, executing source identity, complete pilot jobs and immutable resource limits. `manifest_binding.json` binds the canonical manifest digest, every pilot/proposal specification's byte SHA256, and proposal-manifest byte SHA256. Progress is separate mutable journal metadata. Resume verifies these bindings before launching work.

Each job has problem ID, relative specification path, canonical specification hash, related family, partition, OOD factor, mesh/domain, support, direction/location/magnitude, volume, initialization and scaling regime. Specifications retain the unchanged `m3.3b.problem.v1` native schema, full nodal coordinates/forces/fixed DOFs/material, exact initial design, filter geometry, optimizer controls, seed, and physical scaling semantics. IDs identify complete specifications, rather than merely mesh shape.

The proposed manifest is explicitly `planning_only_not_authorized_for_generation`. All 164 proposed configurations pass serialization, supported-node/load and rigid-body restraint checks; these are specification checks, not FEM convergence tests. Only the seven pilot jobs are executable. Every new trajectory uses feasible_upper_v1, width 1e-8, original bracket/move/bounds, target .001, and at most 500 updates.

Conservative families canonicalize left/right horizontal mirrors and group normalized load location, support, direction and physical aspect. Force magnitude, initialization, volume and resolution variants stay together. Family identity describes a declared grouping policy, not statistically independent physical draws. Continuous-neighbor similarity still requires review. Geometry OOD is deliberately held out; the training aspect range is therefore narrow and should be expanded before broad geometry-learning claims.

Splits are `train`, `validation`, `test_id`, and `test_ood`. Known related variants never cross partitions. Three support/direction classes and four volumes occur in training. Matched OOD controls vary support, extrapolated boundary position, or aspect ratio; absolute point location also changes with geometry. Future 192 resolution extrapolation is a reserved scenario, with no executable FEM specification at that size.

Window tables contain compact native-array address ranges for histories k=1/3 and horizons h=1/5/10. They do not materialize all windows. Training-only policies are uniform windows, uniform problems, uniform families/windows, and family-first/problem/window. Each emitted address records its exact draw probability and stage/horizon identity. Optional stage balancing uses known configured-cap stage boundaries. Sampling changes addresses, never saved dynamics. Termination and quality sidecars are retrospective annotations and not spatial inputs. No normalization statistics use held-out data.

Read-only native loaders have an explicit cache bound of one trajectory by default, at most two. Homogeneous-resolution batches are required; no field interpolation is performed. Profiles preserve native element/node features and document whether mechanics fields require fresh FEM at inference. Raw gradients, force/support and spacing/filter metadata are retained.

Validated sidecars distinguish dynamics validity, change convergence, capped termination, stationarity, strict volume and reference eligibility. Native reference labels remain false. Candidate screening and threshold sensitivity are diagnostic only; caps never become reference designs.

Executing bytes are in `source_snapshots/`, mapped by `source_manifest.json`. To restore, copy each archive to its recorded original relative path beneath a fresh temporary directory, preserving package layout and `.py` suffixes. Archived test `.py.txt` files are documentation and should not be collected accidentally. Run restored code with that directory first on PYTHONPATH and use absolute saved-data paths. The original environment/module versions and thread settings are in `environment.json`. Production resume also requires the original source fingerprints; do not mix later code with earlier journals.
